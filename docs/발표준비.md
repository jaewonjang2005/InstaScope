# Insta Taste Recommender 프로젝트 발표 준비 스크립트

## 🎤 1. 오프닝 (Hook)
"여러분, 인스타그램하면서 '대체 알고리즘은 내가 뭘 좋아한다고 생각하는 걸까?' 궁금해하신 적 없나요? 
흔히 있는 성향 테스트나 MBTI 앱처럼 직관적이고 재밌는 서비스, **'Insta Taste Recommender (인스타 취향 추천기)'**를 기획하게 된 배경입니다.
오늘 저희 팀이 인스타그램의 거대한 데이터 속에서 나의 진짜 취향 키워드를 어떻게 뽑아내는지, 그리고 실시간으로 어떻게 콘텐츠를 추천하는지 공유하겠습니다."

## 💡 2. 문제 정의와 피벗(Pivot)
"초기 저희 프로젝트는 취향 DNA, 알고리즘 폭로, 비밀 컬렉션 등 너무 많은 기능을 한 번에 보여주려 했습니다. 
하지만 기능이 많아질수록 데이터는 무거워지고, 핵심 메시지는 흐려졌습니다.
그래서 과감히 피벗(Pivot)을 결정했습니다. 가장 바이럴 포텐셜이 높고 유저들이 원하는 단 하나의 기능, **'내 인스타 자아(취향) 분석 및 맞춤 추천'**에 모든 리소스를 집중했습니다."

## 🚨 3. 트러블슈팅 1: 민감한 키워드와 검색 엔진 차단 우회
"가장 먼저 부딪힌 벽은 '유저의 숨겨진 취향'이었습니다.
데이터를 분석해보니 일부 민감한 키워드들이 상당수 추출되었습니다. 이를 그대로 검색 엔진에 던지면 필터링 블락에 걸려 스크래핑이 불가능했습니다.
이를 해결하기 위해, 저희는 자체적인 **'안전 매핑 사전(Safe Mapping)'**을 구축하여, 민감한 단어는 일반적인 단어로 치환한 뒤 검색을 수행해 차단을 우회하면서도 취향을 만족시키는 콘텐츠를 가져오는 데 성공했습니다. 더불어 특별한 숨겨진 취향이 아예 없는 유저에게는 '건전한 취향'이라는 Empty State를 제공하여 재미를 더했습니다."

## 🚀 4. 트러블슈팅 2: Vercel 500MB 한계 및 Vector DB 의존성 탈피
"두 번째이자 가장 치명적이었던 문제는 배포 환경과 무거운 아키텍처였습니다.
유저의 ZIP 파일은 보통 800MB에 달해 Vercel 서버가 뻗어버렸고, 추천을 위해 Vector DB를 올리는 것은 엄청난 리소스 낭비였습니다.
저희의 해결책은 **'디스크를 쓰지 말고, DB도 가볍게 쓰자'**였습니다.
`zipfile`을 활용해 메모리 스트리밍 파싱으로 500MB 디스크 한계를 돌파했고, Vector DB 대신 **DuckDuckGo 실시간 웹 스크래핑(DDGS)**을 백엔드에 통합했습니다. 이로 인해 인프라 비용은 0원으로 줄고, 항상 최신 트렌드를 추천받을 수 있게 되었습니다."

## 🏗️ 5. 아키텍처 및 프론트엔드 UI/UX
"또한 최신 성향 테스트 앱들의 UI/UX를 벤치마킹하여 프론트엔드를 개편했습니다. 분석된 1위 키워드를 바탕으로 '당신의 인스타 자아는 [ #동기부여 ] 마니아'와 같이 네이밍을 부여하고, 일반 카테고리와 숨겨진 취향 카테고리를 네온 효과(Glassmorphism)로 시각적으로 분리했습니다. 공유 기능까지 완비되어 있습니다."
