# Insta Taste Recommender 개발 관련 Q&A (질문.md)

부트캠프 스터디 및 멘토링에서 자주 나오는 주요 질문과 답변입니다.

---

### Q1. 인스타그램이 사용자 데이터를 ZIP으로 제공하는 이유는 무엇인가요?
**A:** 유럽연합의 GDPR(일반 데이터 보호 규칙)과 캘리포니아의 CCPA 등 개인정보 보호법에 따라, 플랫폼은 사용자가 자신의 데이터를 요구할 경우 기계가 읽을 수 있는 형식(Machine-Readable Format, JSON 등)으로 제공할 의무가 있기 때문입니다. Insta Taste Recommender는 바로 이 '정보 이동권(Right to Data Portability)'을 활용한 서비스입니다.

### Q2. 취향 키워드 점수 산정 방식은 어떻게 정하셨나요?
**A:** 유저의 행동에 담긴 '무의식적 의도'의 깊이에 따라 가중치를 다르게 부여했습니다.
- `스토리 시청 (1점)`: 가장 수동적이고 가벼운 상호작용
- `게시물 좋아요 (2점)`: 알고리즘에 긍정적인 신호를 주는 능동적 상호작용
- `비밀 저장 (3점)`: 남에게 보이지 않지만 본인이 두고두고 보고 싶어 하는 강력한 내적 호감 지표
- `스토리 좋아요 (4점)`: 피드와 달리 직접 푸시 알림이 가는 프라이빗하고 강력한 호감 표현

### Q3. 백엔드에서 800MB에 달하는 ZIP 파일을 어떻게 Vercel에서 터지지 않고 처리했나요?
**A:** Vercel의 Serverless Function은 `/tmp` 디렉토리에 500MB의 용량 제한이 있습니다.
파이썬의 `zipfile` 모듈을 활용하여 **'압축을 풀지 않고'** 아카이브 내부 경로를 스캔한 후, 필요한 4개의 JSON 파일만 RAM으로 복사해오는 **In-Memory Streaming 추출 기법**을 도입하여 디스크 한계를 돌파했습니다.

### Q4. 민감한 키워드도 검색 추천이 되나요? 안전한가요?
**A:** 네, 분석 중 다소 민감하거나 숨겨진 취향이 발견될 수 있습니다. 
하지만 이를 그대로 검색하면 검색 엔진 차단(Scraping Block)에 걸립니다. 저희는 자체 **Safe Mapping Dictionary**를 구축하여 특정 단어들을 자동 우회 치환한 뒤 검색 엔진에 질의합니다. 따라서 성인 인증 등에 걸리지 않으면서도 유저의 숨겨진 취향을 저격하는 콘텐츠를 안전하게 보여줍니다. 반대로 특별한 숨겨진 키워드가 전혀 없으면 "평범하고 건전한 취향을 가지고 계시네요!"라는 재치 있는 Empty State를 출력합니다.

### Q5. Vector DB 대신 실시간 웹 스크래핑(DDGS)을 쓴 이유는 무엇인가요?
**A:** 가상 데이터(Mock)를 쓰거나 무거운 Vector DB(pgvector/FAISS)를 올리는 것은 서버 리소스 낭비가 심합니다. 저희는 사용자가 데이터를 넣는 즉시 추출된 해시태그를 `duckduckgo-search (ddgs)`를 통해 인터넷(`site:instagram.com`)에서 실시간으로 스크래핑해오도록 아키텍처를 피벗했습니다. 덕분에 DB 부담은 0이 되고, 언제나 최신 트렌드를 추천받을 수 있습니다.
