# InstaScope (인스타 취향 분석기) 20260802 아키텍처 및 구현 명세서

본 문서는 다른 AI 에이전트나 개발자가 본 프로젝트의 구조와 핵심 알고리즘을 완벽하게 이해하고 재구현할 수 있도록 상세히 기록된 명세서입니다.

---

## 1. 프로젝트 개요
- **목적:** 사용자의 인스타그램 백업 데이터(ZIP)를 분석하여 알고리즘이 파악한 사용자의 진짜 취향(1-Pick)과 숨겨진 취향(Secret Pick, NSFW/서브컬처 등)을 분리하여 분석하고 관련된 해시태그 큐레이션을 제공하는 웹 서비스.
- **주요 기능:**
  1. 인스타그램 데이터 ZIP 파일 청크 업로드 (대용량 파일 지원)
  2. JSON 파싱 및 라틴어(latin1) 깨짐(모지바케) 현상 복구
  3. 시계열 기반 가중치(Time Decay) 알고리즘 적용
  4. SFW(건전한 취향)와 Hidden(19금, 서브컬처 등) 키워드의 완벽한 분리 및 추천

---

## 2. 기술 스택 (Tech Stack)
- **Frontend:** React (Vite), TailwindCSS, 3D/글래스모피즘(Glassmorphism) 기반 동적 UI
- **Backend:** FastAPI, Python 3.11+
- **Database:** Supabase (PostgreSQL)
- **Deployment:** Vercel (Frontend & Serverless Functions 배포)

---

## 3. 백엔드 아키텍처 및 핵심 최적화 (Vercel Serverless 극복)

Vercel의 Serverless 함수 제약(1024MB RAM 한계, 10초 타임아웃, C-Extension 지원 불가)을 극복하기 위해 설계된 특수 아키텍처입니다.

### 3.1. 대용량 파일 업로드 및 메모리 뻥튀기 방지 (OOM Fix)
- **Chunk Upload (`routes.py`):** 프론트엔드에서 파일을 1MB 단위로 쪼개어 `/api/upload-chunk`로 전송. 백엔드는 이를 Vercel의 `/tmp` 디렉토리에 병합.
- **디스크 스트리밍 파싱 (`parser.py`):** 
  - 압축 해제 시 전체 데이터를 메모리에 올리지 않고, 분석에 필요한 딱 5개의 JSON 파일만 `/tmp` 디스크에 스트리밍하여 추출.
  - JSON 로드(`json.load`) 후 Python DOM을 전체 복제하며 디코딩(`decode_obj`)하지 않고, **필요한 순간(해시태그, 날짜 추출)에만 `decode_insta_text`를 호출**하여 1GB 메모리 크래시(OOM)를 완벽히 해결.

### 3.2. C-Extension 크래시 방지 및 속도 최적화 (`search_service.py`)
- 기존 `duckduckgo_search` 모듈은 내부적으로 `curl_cffi` (C언어 바인딩)를 사용하여 Vercel AL2 환경에서 **Segmentation Fault(1.47초 크래시)** 를 유발.
- 이를 해결하기 위해 크롤링 로직을 전면 제거하고, 추출된 키워드를 즉시 **인스타그램 해시태그 검색 URL (`https://www.instagram.com/explore/tags/{keyword}/`)로 자체 생성(Generator)** 하여 0.01초 만에 안전하게 응답하도록 설계.

## 4. 핵심 알고리즘 로직 (`keyword_extractor.py`)

### 4.1. "껍데기(폴더명) 무시, 콘텐츠 분석" 알고리즘
저장된 폴더(Collection)의 이름은 사용자가 임의로 짓기 때문에 신뢰할 수 없습니다. 
- `parser.py`의 `_extract_collections`는 컬렉션의 이름이 아닌 **컬렉션 내부 게시물들의 해시태그 밀도(Density)** 를 측정.
- **밀도 30% 이상**의 특정 해시태그 군집이 발견될 경우, 이는 강력한 '숨겨진 취향(Secret Pick)'으로 강제 추출됨.

### 4.2. 최신화(Time Decay) 가중치 알고리즘
단순 빈도수(Count)가 아니라 **최근에 관심 가진 항목**이 현재 인스타 알고리즘에 더 큰 영향을 미칩니다.
- **기본 가중치:** 저장한 스토리(4.0) > 저장된 게시물(3.0) > 좋아요(2.0) > 스토리 조회(1.0)
- **시간 가중치:** 
  - 최근 30일 이내 상호작용: `기본 가중치 x 3.0`
  - 최근 180일 이내 상호작용: `기본 가중치 x 1.5`
  - 그 외 과거: `기본 가중치 x 1.0`

### 4.3. 취향 분리 및 우회 (SFW vs NSFW)
- `HIDDEN_MAPPING`: 19금, 노출, 섹시 관련 키워드를 '바디프로필', '매력적인', '비키니' 등의 SFW 대체재로 매핑.
- `classify_tag_type()` 함수로 해시태그를 `EXPLICIT_HIDDEN`, `IMPLICIT_HIDDEN`, `SFW` 3가지 카테고리로 분리.
- 분석 결과는 `search_sfw_queries` (일반 취향)와 `search_hidden_queries` (비밀 취향)로 분리되어 프론트엔드로 전달.

## 6. 미래 확장을 위한 가이드
이 앱을 바탕으로 추후 모델을 훈련하거나 추가 기능을 붙이는 AI를 위한 조언:
1. **의존성(Dependencies):** Vercel 환경에서는 C-Extension이 포함된 패키지(예: `curl_cffi`, 일부 ML 라이브러리)를 설치할 때 주의해야 합니다. 크래시가 나면 `search_service.py`처럼 순수 Python 모듈이나 외부 API 호출로 우회해야 합니다.
2. **가비지 컬렉션(GC):** `routes.py`에서 임시 생성된 디렉토리(`/tmp`)는 분석 완료 시 즉각 `shutil.rmtree`로 삭제해야 파일 누수로 인한 디스크 부족이 발생하지 않습니다.
3. **한글 깨짐 복구 규칙:** 인스타그램 JSON은 `latin1` 인코딩 버그를 가지고 있으므로 항상 `encoding.py`의 `decode_insta_text`를 통해 `.encode('latin1').decode('utf-8')` 파이프라인을 타야 한글이 제대로 노출됩니다.
