# InstaScope 알고리즘 리팩토링 종합 보고서 (학회 발표용)

## 1. 프로젝트 개요 및 배경
**InstaScope**는 사용자의 인스타그램 활동 데이터(좋아요, 저장, 스토리 시청 등)를 분석하여 사용자의 '일반 취향', '서브 취향(은밀한 취향)', '매운맛 취향'을 도출해 내는 서비스입니다. 
초기 앱 구조에서는 하드코딩된 사전(Dictionary)과 단순 빈도수(Global Top-K)를 바탕으로 키워드를 추출했으나, 이는 사용자의 딥(deep)한 취향을 정확하게 파악하지 못하고 여러 주제가 혼재되어 출력되는 치명적인 한계를 보였습니다.

---

## 2. 기존 아키텍처의 문제점 및 에러

### 2.1. 프론트엔드 - 매운맛 토글(Toggle) 렌더링 버그
* **증상**: 사용자가 서브 취향 페이지에서 '매운맛🔥' 토글을 켰을 때, 화면의 텍스트 색상만 변경되고 실제 키워드 뱃지나 추천 콘텐츠는 일반 서브 취향 그대로 유지되는 현상.
* **원인**: React 상태 관리(`SecretPickPage.jsx`)에서 토글 조건부 렌더링 시, 백엔드에서 받아온 매운맛 전용 데이터(`raw_hidden_tags`, `spicy_recommendations`)를 상태 변수에 덮어씌우는 조건문이 논리적으로 누락되어 있었습니다.

### 2.2. 백엔드 - 주제 불일치 (Thematic Inconsistency)
* **증상**: 메인 키워드가 `#동기부여`인데, 하위 키워드로 `#jpop`, `#fyp` 등 전혀 상관없는 키워드들이 혼재되어 출력.
* **원인**: 사용자의 인스타그램 데이터 전체에서 단순히 '가장 많이 등장한 태그 5개'를 무조건 1등부터 5등까지 잘라오는 **Global Top-K 방식**을 사용했기 때문입니다. 사용자가 평소 '동기부여'와 'jpop'을 둘 다 자주 본다면, 두 카테고리가 강제로 하나의 결과 창에 합쳐지게 됩니다.

### 2.3. 프론트엔드 - UX/UI 워딩 개선 (Wording Update)
* **증상**: 매운맛 페이지의 설명에 "19금/서브컬처"라는 직설적인 단어가 포함되어 있어 사용자에게 거부감을 줄 우려가 있었습니다.
* **해결**: 사용자 피드백을 즉각 반영하여 직설적인 단어를 배제하고, "본능적이고 원초적인 매운맛 키워드만을" 이라는 은유적이고 세련된 표현으로 UX를 개선했습니다.

## 3. 아이디에이션 및 해결 전략 (Communication & Ideation)

### 3.1. 사용자(연구자) 철학의 수용
오류 수정 과정에서 연구자님은 **"절대 단어장(Dictionary)을 하드코딩해서 분류하지 마라. 사람들의 취향은 무한하므로 하드코딩으로는 모든 취향을 커버할 수 없다"**는 핵심 철학을 제시하셨습니다.
이에 따라 기존 코드에 남아있던 하드코딩 의존성을 완전히 제거하고, 순수하게 사용자의 시청 패턴 내에서 문맥을 찾아내는 수학적 알고리즘 설계로 방향을 틀었습니다.

### 3.2. 해결책 제안: 동시 출현 네트워크 (Co-occurrence Tracking)
단어장 없이 주제의 일관성을 유지하기 위해, **'같은 게시물(릴스) 안에서 함께 사용된 해시태그들은 서로 깊은 연관성이 있다'**는 가설을 세웠습니다.
* **기존**: 전체 게시물을 뜯어서 제일 많이 나온 순서대로 나열.
* **신규 (Co-occurrence)**: 1등 키워드를 '메인 주제'로 선정한 뒤, 나머지 4개는 **오직 1등 키워드와 같은 게시물 안에서 등장했던(묶여 다녔던) 키워드**들 중에서만 엄선.

## 4. 알고리즘 구현 및 자료 구조 (Implementation)

### 4.1. 자료 구조 설계
백엔드(`keyword_extractor.py`)의 메모리 내에서 해시태그 간의 네트워크를 구축하기 위해 다음과 같은 자료 구조를 사용했습니다.

* `tag_stats` (Dictionary): 각 태그의 총 등장 횟수(doc_count) 및 공개/비공개 활동 가중치 점수 기록.
* **`co_occurrences` (Dictionary of Dictionaries)**: 네트워크 그래프의 인접 리스트(Adjacency List) 역할. 
  * 구조: `{ "태그A": { "태그B": 가중치점수, "태그C": 가중치점수 } }`
  * 게시물을 파싱할 때마다, 한 게시물에 등장한 유일한 태그들의 모든 쌍(Pair)을 조합하여 가중치를 누적합니다. (최근 게시물일수록 가중치 상승)

### 4.2. 실행 로직 (Keyword Selection Logic) 및 시간 감쇠(Time Decay) 가중치
개발 과정 중, 단순 누적 빈도수(`doc_count`)로만 1등을 뽑을 경우 1년 전의 과거 데이터가 최근의 취향을 압도해버리는 문제(과적합)가 발견되었습니다. 이를 해결하기 위해 최근 데이터일수록 높은 점수를 부여하는 **Time Decay Weighting(시간 감쇠 가중치)**를 적용하여 `weighted_count`를 산출했습니다. (1달 이내: 3배, 6개월 이내: 1.5배, 1년 이상: 0.2배)

1. **SFW (일반 취향)**: `weighted_count`가 가장 높은 태그를 메인으로 선정하고, `co_occurrences`를 참조하여 메인 태그와 가장 연관 점수가 높은 4개의 SFW 태그를 가져옵니다.
2. **Secret (서브 취향)**: Private Ratio(공유/저장 비율)가 높은 후보군 중 `weighted_count` 최상위 태그를 메인 카테고리(예: `#북리뷰`)로 잡은 뒤, **전체 SFW 태그 풀(Pool)**을 순회하며 일상 태그(예: `#독서`, `#책추천`)를 끌어옵니다. (기존 10개 제한에서 전체 풀로 확장하여 연관성 극대화)
3. **Spicy (매운맛 취향)**: 매운맛 태그 중 `weighted_count`가 가장 높은 것을 메인으로 잡고, 마찬가지로 전체 풀을 순회하여 연관 태그(예: `#비키니` -> `#해운대`, `#다이어트`)를 자연스럽게 엮어냅니다.

> **에러 핫픽스 회고**: 알고리즘 교체 과정 중, 중복 단어를 필터링하는 `filter_similar_tags` 함수가 실수로 유실되어 파이썬 `NameError (HTTP 500)`가 발생했습니다. 즉시 서버 로그를 분석해 원인을 규명하고 함수를 복원하는 긴급 패치(Hotfix)를 진행하여 시스템 안정성을 회복했습니다.

## 5. 전체 앱 스트럭처 요약 (App Structure)

* **[Frontend - React]**
  * `ResultPage.jsx`: 사용자의 일반(SFW) 취향을 보여주는 메인 페이지. 추출된 거시적 카테고리와 뱃지 렌더링.
  * `SecretPickPage.jsx`: 서브 취향 / 매운맛 취향 렌더링. 상단의 토글 스위치 상태(`isSpicyMode`)에 따라 렌더링되는 변수 스코프(`hidden` vs `spicy`)를 완벽히 분리.
* **[Backend - Python / FastAPI]**
  * `main.py`: Vercel Serverless 함수로 동작하며, 프론트엔드로부터 JSON 덤프 파일을 수신.
  * `parser.py`: JSON 데이터(좋아요, 저장, 스토리 등)를 메모리 상의 파이썬 리스트 구조로 파싱.
  * `keyword_extractor.py`: (핵심 모듈) **Co-occurrence 기반 알고리즘**을 통해 SFW, Secret, Spicy 3가지 계층의 취향 카테고리를 추출 및 반환.

## 6. 결론 및 성과
이번 리팩토링을 통해 InstaScope는 단순한 빈도수 기반 통계 툴에서 벗어나, **사용자 맞춤형 문맥 기반(Context-aware) 추천 엔진**으로 진화했습니다. 하드코딩된 사전 없이도 해시태그 간의 수학적 위상(Topology)을 분석하여 어떠한 매니악한 취향이라도 정확한 묶음으로 파악할 수 있는 유연하고 강력한 스케일러빌리티(Scalability)를 확보했습니다.

## 7. 인프라 모니터링 및 데이터베이스 장애 대응 (추가 업데이트)

### 7.1. 웹 성능 및 방문자 통계 추적
사용자의 유입과 사이트 렌더링 성능을 체계적으로 추적하기 위해 프론트엔드(`React`) 단에 Vercel 공식 모니터링 툴을 탑재했습니다.
* `@vercel/speed-insights/react`: 유저의 페이지 로딩 속도, Core Web Vitals 추적.
* `@vercel/analytics/react`: 방문자 수, 국가, 기기, 접속 페이지 통계 분석.

### 7.2. 수파베이스(Supabase) RLS 장애 방어와 Memory Fallback
수파베이스 DB의 보안 정책(RLS, Row Level Security)이 켜져 있거나 DB 연결에 실패하는 경우, 사용자가 에러 화면(HTTP 500)을 마주하게 되는 치명적 문제를 방지했습니다.
* **장애 방어 설계**: DB Insert가 실패할 경우 예외처리(Exception)로 에러를 잡은 뒤, Vercel 서버의 **임시 메모리(Memory Store)**에 1회용으로 결과를 저장하여 화면으로 응답합니다.
* **효과**: 백그라운드 DB 저장에 실패하더라도 프론트엔드 유저는 문제없이 200 OK와 함께 정상적인 분석 화면을 볼 수 있도록 무중단(Graceful Degradation) UX를 제공합니다.
