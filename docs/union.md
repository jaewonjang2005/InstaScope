# [비전공자도 이해하는] InstaScope 서비스 구축 풀스토리

## 1. 프로젝트의 시작: "내 인스타 알고리즘은 대체 날 뭐라고 생각할까?"
인스타그램을 하다 보면 가끔 엉뚱한 광고나 릴스가 뜨기도 하고, 내가 남몰래 좋아하는 것들이 귀신같이 연속으로 뜨기도 합니다.
"대체 인스타그램 알고리즘은 나를 어떤 사람이라고 정의하고 있을까?"라는 궁금증에서 출발한 것이 바로 **InstaScope (인스타 취향 추천기)** 프로젝트입니다.

처음 아이디에이션 단계에서는 '나를 언팔로우 한 사람 추적', 'DM으로 보는 성격 분석' 등 기능이 너무 많았습니다. 하지만 모든 기능을 다 넣으려다 보니 데이터 처리가 무거워지고 프로젝트의 색깔이 흐려졌습니다.
그래서 가장 바이럴(입소문) 퍼텐셜이 높고 유저들이 재밌어할 단 하나의 핵심 기능에 집중하기로 했습니다.
바로 **'내 인스타 활동 데이터를 분석해 진짜 나의 취향(자아)을 폭로하는 것'**입니다.

## 2. 데이터의 원천: 인스타그램 정보는 어떻게 생겼을까? (JSON 구조)
우리의 취향을 분석하기 위해서는 인스타그램 서버에서 사용자의 활동 기록을 직접 다운로드 받아야 합니다.
다운로드 받은 압축(ZIP) 파일 안에는 수많은 `JSON` 파일들이 들어 있습니다. JSON이란 컴퓨터가 쉽게 읽을 수 있도록 텍스트를 규칙적인 이름표(Key)와 내용(Value)으로 나열한 데이터 구조입니다.
우리는 수십 개의 JSON 파일 중 **가장 중요한 3가지 데이터**만 쏙 골라서 분석합니다.

1. **좋아요 (likes.json)**: 내가 남들에게 대놓고 드러내는 '일반적인 취향'을 파악하는 핵심 단서.
2. **저장됨 (saved_posts.json)**: 남들에게 보여주기 부끄럽지만 나만 몰래 간직하고 싶은 '비밀 컬렉션(서브 취향)'의 1등 단서.
3. **스토리 반응 (story_likes.json)**: 24시간만 떠있는 스토리에 흔적을 남겼다는 것은 정말 관심이 많다는 뜻! 이상형이나 호감도를 역추적하는 강력한 데이터.

## 3. 핵심 엔진: 단순 무식한 방법(하드코딩)을 버리고 '수학적 문맥'을 입히다
처음 인공지능 알고리즘을 짤 때는 "A라는 태그는 운동, B라는 태그는 19금" 이런 식으로 컴퓨터에게 미리 단어장(사전)을 주입시켜 놓고 억지로 분류하려고 했습니다(하드코딩).
하지만 사람들의 취향은 무한하고 트렌드는 매일 바뀝니다. 컴퓨터에게 세상 모든 유행어를 일일이 가르칠 수는 없었죠.

그래서 **'동시 출현(Co-occurrence) 네트워크'**라는 똑똑한 수학 모델을 도입했습니다.
* **작동 원리**: '같은 릴스나 게시물 안에서 같이 쓰인 해시태그들은 서로 깊은 연관성이 있다'는 가설입니다.
* 예를 들어, `#비키니`라는 태그가 많이 발견되면 미리 정해진 단어장이 없어도, 컴퓨터가 그 게시물에 같이 적혀있던 `#해운대`, `#다이어트`, `#여름휴가`를 알아서 하나의 '매운맛 취향' 묶음으로 엮어냅니다.
* **시간 감쇠(Time Decay)**: 1년 전의 옛날 관심사가 오늘의 관심사를 이기면 안 되겠죠? 최근에 누른 좋아요일수록 최고 3배 더 높은 점수(가중치)를 주도록 설계하여 '진짜 지금 나의 트렌드'를 예리하게 짚어냅니다.

이 과정을 거치면서 시스템은 내 안의 세 가지 자아를 뽑아냅니다.
1. **일반 취향 (SFW)**: 동기부여, 독서 등 겉으로 드러나는 나의 주된 메인 관심사.
2. **서브 취향 (Secret)**: 책 추천, 일상 꿀팁 등 나만 조용히 저장해 둔 유용한 정보들.
3. **매운맛 취향 (Spicy)**: 본능적이고 원초적으로 끌렸던 은밀한 키워드 묶음.

## 4. 백엔드와 인프라: 엄청난 크기의 데이터를 뚫어라!
이런 멋진 알고리즘을 만들었지만 현실적인 '서버(컴퓨터) 용량' 문제에 부딪혔습니다.
유저가 올리는 인스타그램 ZIP 파일은 보통 800MB에 달하는데, 우리가 빌려 쓰는 무료 서버(Vercel)는 디스크 용량이 500MB밖에 안 되어서 서버가 뻗어버렸습니다.

* **해결책 (인-메모리 파싱)**: 무거운 파일을 서버 하드디스크에 아예 저장하지 않고, 컴퓨터의 '임시 뇌(메모리 RAM)'에 공중부양 시켜놓고 우리가 필요한 좋아요/저장 기록만 빨대 꽂듯 쏙쏙 빨아먹은 뒤 바로 파일을 증발시키는 마법을 부렸습니다. 비용 0원으로 대용량 처리가 가능해진 것이죠!
* **장애 방지 (Memory Fallback)**: 만약 최종 결과를 영구적으로 저장하는 데이터베이스(Supabase)가 보안 설정이나 네트워크 문제로 저장을 거부하더라도, 유저에게는 에러 화면을 띄우지 않고 임시 메모리에서 바로 화면을 띄워주는 무중단(Graceful Degradation) 안전 설계도 적용했습니다.

## 5. 프론트엔드: 사용자가 가장 즐거워할 예쁜 화면 만들기
서버에서 데이터를 멋지게 분석했다면, 이제 예쁜 화면으로 포장할 차례입니다.
최신 유행하는 MBTI 심리 테스트 앱들처럼, 분석된 결과를 바탕으로 **"당신의 인스타 자아는 [ #동기부여 ] 마니아"** 같은 재치 있는 네이밍을 부여했습니다.

특히 사용자가 불쾌하지 않고 재밌게 느낄 수 있도록 단어 선택(워딩)에 심혈을 기울였습니다.
'19금/서브컬처' 같은 직설적이고 거북할 수 있는 단어 대신, **"본능적이고 원초적인 매운맛 취향🔥"**이라는 세련되고 센스 있는 표현을 사용하여 사용자 경험(UX)을 대폭 끌어올렸습니다.

마지막으로, 우리 앱에 하루에 몇 명이 들어오고 로딩 속도는 얼마나 빠른지 실시간으로 모니터링하기 위해 `Vercel Analytics`와 `Speed Insights`라는 추적 시스템을 화면 뒤에 몰래 달아두어 데이터 수집 기반까지 완비했습니다.

## 6. 최종 결론
InstaScope는 단순한 통계 장난감이 아닙니다.
무료 서버의 제한적인 환경 속에서도 대용량 데이터를 부드럽게 처리하는 '엔지니어링 기술', 하드코딩의 낡은 방식을 버리고 문맥을 스스로 찾아내는 '수학적 알고리즘', 그리고 사용자의 심리를 배려해 은밀한 재미를 주는 'UI/UX 기획'까지 모든 것이 톱니바퀴처럼 맞물린 하나의 완전한 프로덕트입니다.
