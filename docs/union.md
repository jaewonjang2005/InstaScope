# [비전공자도 이해하는] InstaScope 서비스 구축 풀스토리

## 1. 프로젝트의 시작: "내 인스타 알고리즘은 대체 날 뭐라고 생각할까?"
인스타그램을 하다 보면 가끔 엉뚱한 광고나 릴스가 뜨기도 하고, 내가 남몰래 좋아하는 것들이 귀신같이 연속으로 뜨기도 합니다.
"대체 인스타그램 알고리즘은 나를 어떤 사람이라고 정의하고 있을까?"라는 궁금증에서 출발한 것이 바로 **InstaScope (인스타 취향 추천기)** 프로젝트입니다.

처음 아이디에이션 단계에서는 '나를 언팔로우 한 사람 추적', 'DM으로 보는 성격 분석' 등 기능이 너무 많았습니다. 하지만 모든 기능을 다 넣으려다 보니 데이터 처리가 무거워지고 프로젝트의 색깔이 흐려졌습니다.
그래서 가장 바이럴(입소문) 퍼텐셜이 높고 유저들이 재밌어할 단 하나의 핵심 기능에 집중하기로 했습니다.
바로 **'내 인스타 활동 데이터를 분석해 진짜 나의 취향(자아)을 폭로하는 것'**입니다.

## 2. 데이터의 원천: 인스타그램 정보는 어떻게 생겼을까? (JSON 구조)
우리의 취향을 분석하기 위해서는 인스타그램 서버에서 사용자의 활동 기록을 직접 다운로드 받아야 합니다.
다운로드 받은 압축(ZIP) 파일 안에는 수많은 `JSON` 파일들이 들어 있습니다. JSON이란 컴퓨터가 쉽게 읽을 수 있도록 텍스트를 규칙적인 이름표(Key)와 내용(Value)으로 나열한 데이터 구조입니다.
우리는 수십 개의 JSON 파일 중 **가장 중요한 3가지 데이터**만 쏙 골라서 분석합니다.

1. **좋아요 (likes.json)**: 내가 남들에게 대놓고 드러내는 '일반적인 취향'을 파악하는 핵심 단서.
2. **저장됨 (saved_posts.json)**: 남들에게 보여주기 부끄럽지만 나만 몰래 간직하고 싶은 '비밀 컬렉션(서브 취향)'의 1등 단서.
3. **스토리 반응 (story_likes.json)**: 24시간만 떠있는 스토리에 흔적을 남겼다는 것은 정말 관심이 많다는 뜻! 이상형이나 호감도를 역추적하는 강력한 데이터.

## 3. 핵심 엔진: 단순 무식한 방법(하드코딩)을 버리고 '수학적 문맥'을 입히다
처음 인공지능 알고리즘을 짤 때는 "A라는 태그는 운동, B라는 태그는 19금" 이런 식으로 컴퓨터에게 미리 단어장(사전)을 주입시켜 놓고 억지로 분류하려고 했습니다(하드코딩).
하지만 사람들의 취향은 무한하고 트렌드는 매일 바뀝니다. 컴퓨터에게 세상 모든 유행어를 일일이 가르칠 수는 없었죠.

그래서 **'동시 출현(Co-occurrence) 네트워크'**라는 똑똑한 수학 모델을 도입했습니다.
* **작동 원리**: '같은 릴스나 게시물 안에서 같이 쓰인 해시태그들은 서로 깊은 연관성이 있다'는 가설입니다.
* 예를 들어, `#비키니`라는 태그가 많이 발견되면 미리 정해진 단어장이 없어도, 컴퓨터가 그 게시물에 같이 적혀있던 `#해운대`, `#다이어트`, `#여름휴가`를 알아서 하나의 '매운맛 취향' 묶음으로 엮어냅니다.
* **시간 감쇠(Time Decay)**: 1년 전의 옛날 관심사가 오늘의 관심사를 이기면 안 되겠죠? 최근에 누른 좋아요일수록 최고 3배 더 높은 점수(가중치)를 주도록 설계하여 '진짜 지금 나의 트렌드'를 예리하게 짚어냅니다.

이 과정을 거치면서 시스템은 내 안의 세 가지 자아를 뽑아냅니다.
1. **일반 취향 (SFW)**: 동기부여, 독서 등 겉으로 드러나는 나의 주된 메인 관심사.
2. **서브 취향 (Secret)**: 책 추천, 일상 꿀팁 등 나만 조용히 저장해 둔 유용한 정보들.
3. **매운맛 취향 (Spicy)**: 본능적이고 원초적으로 끌렸던 은밀한 키워드 묶음.

## 4. 백엔드 (Python/FastAPI): 엄청난 데이터를 요리하는 공장
우리의 백엔드는 파이썬(Python)과 FastAPI 프레임워크로 만들어져 있습니다. 수십만 개의 데이터가 들어와도 빠르고 안정적으로 처리하기 위해, 기능별로 방(모듈)을 아주 깔끔하게 쪼개놓았습니다.

### 4.1. routes.py & zip_extractor.py (기가바이트급 택배 수령과 해체쇼)
프론트엔드에서 잘게 쪼개서(Chunk) 보낸 800MB짜리 ZIP 파일 조각들을 `routes.py`가 안전하게 모아서 조립합니다. 
문제는 우리가 빌려 쓰는 무료 서버(Vercel)의 하드디스크 용량이 500MB밖에 안 된다는 점입니다. 압축을 풀면 서버가 뻗어버리죠.
그래서 `zip_extractor.py`가 마법을 부립니다. 무거운 파일을 하드디스크에 아예 저장하지 않고, 컴퓨터의 **'임시 뇌(메모리 RAM)'**에 공중부양 시켜놓고 압축을 푼 뒤, 우리가 필요한 `likes.json` 같은 알맹이만 빨대 꽂듯 쏙쏙 빼내고 파일 전체를 공중에서 바로 증발(삭제)시킵니다. 비용 0원으로 대용량 처리가 가능해진 핵심 기술입니다.

### 4.2. parser.py (복잡한 인스타 미로 탐색기)
인스타그램이 준 압축 파일 안에는 수만 개의 폴더와 파일이 복잡하게 얽혀 있습니다. `parser.py`는 이 미로 속을 돌아다니며 정확히 '좋아요', '저장됨', '스토리 반응' 폴더만 찾아내어 그 안에 적힌 글자들을 예쁘게 정리된 명단으로 만들어 다음 방으로 넘겨줍니다.

### 4.3. keyword_extractor.py (취향을 꿰뚫어보는 수학자)
우리 프로젝트의 진짜 심장(엔진)입니다. 여기서 앞서 말한 **동시 출현(Co-occurrence)**과 **시간 감쇠(Time Decay)** 알고리즘이 돌아갑니다.
* 최신 트렌드를 파악하기 위해, 최근 날짜에 누른 좋아요일수록 `weight(가중치)` 점수를 3배로 뻥튀기하는 계산식이 들어있습니다.
* 단어장을 일일이 주입하는 하드코딩 방식 대신, 글과 글 사이의 연관성을 수학적으로 묶어서 하나의 군집(자아)으로 만들어 냅니다.

### 4.4. search_service.py (덕덕고 실시간 검색 요원)
우리가 찾아낸 핵심 해시태그(예: `#비키니`)가 일반 취향인지 매운맛 취향인지 컴퓨터가 어떻게 스스로 판단할까요?
거대한 AI DB를 구축하는 대신, 우리는 백엔드 코드에서 **DuckDuckGo(덕덕고)**라는 검색 엔진에 실시간으로 검색을 시키는 우회로를 뚫었습니다. 
만약 검색 결과에 민감한 단어가 걸리면 안전한 단어로 치환하는 필터링(Safe Mapping) 로직을 거쳐서, 19금 차단에 걸리지 않으면서도 유저의 매운맛 취향을 완벽하게 저격하는 꼼수를 구현했습니다.

### 4.5. db_service.py (서버 뻗음 방지, 무중단 방어막)
분석된 최종 결과를 데이터베이스(Supabase)에 저장하는 역할을 합니다. 하지만 만약 DB 보안 설정이 막혀있거나 네트워크 에러가 나면 어떻게 될까요? 원래대로라면 유저 화면에 시뻘건 '500 에러'가 뜨며 앱이 죽어야 합니다.
하지만 우리는 **예외 처리(Exception handling)**를 꼼꼼히 짜두었습니다. DB 저장이 실패하면 에러를 꿀꺽 삼키고, 결과를 서버의 임시 메모리에 1회용으로 살짝 띄워놓은 뒤 유저 화면으로 보내줍니다(Memory Fallback). 유저 입장에서는 뒤에서 무슨 에러가 났든 전혀 모르게 부드럽고 정상적인 결과 화면을 보게 됩니다.

## 5. 프론트엔드 (React): 사용자 경험(UX)과 기술의 만남
서버에서 데이터를 멋지게 분석했다면, 이제 예쁜 화면으로 포장하고 사용자와 소통할 차례입니다. 우리는 최신 웹 기술인 **React(리액트)**를 사용하여 부드럽고 빠른 싱글 페이지 애플리케이션(SPA)을 구축했습니다.

우리가 만든 프론트엔드 코드의 핵심 구성 요소(Component)들은 다음과 같이 역할이 나뉘어 있습니다.

### 5.1. App.jsx (컨트롤 타워와 모니터링)
앱의 전체적인 뼈대를 잡아주는 곳입니다. 사용자가 어떤 주소로 들어가느냐에 따라 적절한 화면(업로드, 로딩, 결과)을 띄워주는 라우터(Router) 역할을 합니다.
특히, 우리 앱에 하루에 몇 명이 들어오고 로딩 속도는 얼마나 빠른지 실시간으로 감시하기 위해 `Vercel Analytics`와 `Speed Insights`라는 추적 시스템 코드를 화면 뒤에 몰래 달아두어 데이터 수집 기반까지 완비했습니다.

### 5.2. UploadPage.jsx (기가바이트급 업로드 쪼개기)
유저가 올리는 인스타그램 ZIP 파일은 엄청나게 큽니다. 통째로 서버에 던지면 중간에 끊기거나 에러가 나기 쉽죠. 
그래서 프론트엔드 코드 단에서 **'청크(Chunk) 업로드'**라는 기술을 구현했습니다. 큰 파일을 브라우저에서 잘게(예: 10MB씩) 쪼갠 뒤 여러 번 나누어 서버로 안전하게 배달하는 똑똑한 우체부 역할을 합니다.

### 5.3. LoadingPage.jsx (지루할 틈 없는 대기실)
서버가 수십만 개의 데이터를 분석하는 동안 유저가 지루하지 않게 돕는 곳입니다. "혹시 내 폰이 멈췄나?" 의심하지 않도록, 백엔드 서버에 지속적으로 "다 됐어? 다 됐어?" 물어보는 **폴링(Polling)** 코드가 작성되어 있습니다. 분석이 끝났다는 신호(Success)를 받으면 즉시 결과 페이지로 화면을 넘겨줍니다.

### 5.4. ResultPage.jsx & SecretPickPage.jsx (결과 렌더링과 상태 관리)
분석된 결과를 예쁘게 그려내는 스케치북입니다.
* **센스 있는 워딩**: 최신 유행하는 MBTI 심리 테스트 앱들처럼, 분석된 1위 키워드를 바탕으로 **"당신의 인스타 자아는 [ #동기부여 ] 마니아"** 같은 재치 있는 네이밍을 부여했습니다. '19금' 같은 직설적 단어 대신 **"본능적이고 원초적인 매운맛 취향🔥"**이라는 세련된 표현을 코드에 심어 사용자 경험(UX)을 대폭 끌어올렸습니다.
* **상태 관리(State)의 마법**: 서브 취향 페이지(`SecretPickPage`)에는 '매운맛 토글 버튼'이 있습니다. 버튼을 누를 때마다 화면 전체를 새로고침하는 것이 아니라, 리액트의 `useState`라는 기능을 활용하여 내부에 담긴 변수(일반 태그 데이터 ↔ 매운맛 태그 데이터)만 휙휙 교체합니다. 화면 깜빡임 없이 글자와 테마 색상(파란색 ↔ 빨간색)만 부드럽게 바뀌는 마법 같은 UI를 코드로 구현했습니다.

## 6. 데이터베이스 (Supabase): 안전하고 영구적인 데이터 창고
분석이 완료된 결과는 유저가 나중에도 볼 수 있도록 DB에 저장되어야 합니다. 우리는 전통적인 SQL 데이터베이스(PostgreSQL)를 현대적으로 만든 **Supabase(수파베이스)**를 사용했습니다.

### 6.1. 테이블 구조 (Table Schema)
데이터베이스 안에는 `insta_analysis_results`라는 표(Table)가 하나 있습니다.
* **job_id**: 유저가 파일을 올릴 때 발급받는 고유한 영수증 번호(UUID)입니다. 유저는 이 번호를 가지고 언제든 자기 결과를 다시 찾아볼 수 있습니다.
* **result_data**: 일반 취향 1~5위, 매운맛 취향 1~5위 등 백엔드가 분석해 낸 모든 최종 결과물을 'JSON' 형태로 압축해서 딱 한 칸에 욱여넣어 저장합니다. 구조가 아주 단순하고 깔끔합니다.

### 6.2. RLS (Row Level Security) 방패
수파베이스에는 RLS라는 강력한 문지기가 있습니다. 아무나 DB에 쓰레기 데이터를 넣거나 남의 취향을 훔쳐보지 못하게 막는 보안 정책입니다.
우리는 백엔드 서버(API)에서만 데이터를 집어넣고, 프론트엔드에서는 오직 자신의 `job_id` 영수증 번호를 아는 사람만 자기 결과를 조회할 수 있도록 규칙을 설정해 두었습니다.

## 7. 전체 풀스택 (Full-Stack) 데이터 흐름도
지금까지 설명한 프론트엔드(React), 백엔드(Python), DB(Supabase)가 어떻게 하나의 거대한 공장처럼 맞물려 돌아가는지 요약해 볼까요?

1. **[프론트엔드]** 유저가 800MB짜리 인스타 ZIP 파일을 화면에 드래그 앤 드롭합니다.
2. **[프론트엔드]** 브라우저가 이 거대한 파일을 10MB씩 잘게 썰어서(Chunk) 백엔드로 쏩니다.
3. **[백엔드]** 백엔드는 조각들을 허공(메모리)에서 조립한 뒤, 껍질을 까고 `likes.json` 등 필수 데이터만 쏙 빼고 찌꺼기는 다 날려버립니다. (서버 용량 방어)
4. **[백엔드]** 수학적 알고리즘(시간 감쇠 + 동시 출현)을 돌려 유저의 취향 1~5위를 뽑아냅니다.
5. **[백엔드]** 뽑아낸 취향 단어들을 덕덕고(DuckDuckGo) 검색 엔진에 물어봐서 매운맛인지 일반맛인지 안전하게(Safe Mapping) 분류합니다.
6. **[DB]** 완성된 최종 분석 리포트를 수파베이스 `insta_analysis_results` 창고에 영수증 번호(`job_id`)와 함께 저장합니다.
7. **[프론트엔드]** 대기실 화면에서 "다 됐어?"라고 묻던 프론트엔드가 영수증 번호를 받아 DB에서 데이터를 꺼내옵니다.
8. **[프론트엔드]** 예쁜 네온사인 UI와 재치 있는 워딩(매운맛 취향🔥)으로 포장하여 유저의 스마트폰 화면에 최종 결과를 짠! 하고 보여줍니다.

## 8. 최종 결론
InstaScope는 단순한 통계 장난감이 아닙니다.
무료 서버의 제한적인 환경 속에서도 대용량 데이터를 부드럽게 처리하는 '엔지니어링 기술', 하드코딩의 낡은 방식을 버리고 문맥을 스스로 찾아내는 '수학적 알고리즘', 그리고 사용자의 심리를 배려해 은밀한 재미를 주는 'UI/UX 기획'까지 모든 것이 톱니바퀴처럼 맞물린 하나의 완전한 프로덕트입니다.
